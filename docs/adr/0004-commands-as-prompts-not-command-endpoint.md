# Slash commands are normal prompts, never opencode's command endpoint

A chat command (`/name args`, where `name` is a vault or app skill) is sent through the normal prompt path: the user's text as the visible part, the expanded skill text as a hidden (`synthetic`) text part of the same message. The backend never calls opencode's `POST /session/:id/command`. That endpoint expands `` !`…` `` shell snippets and `@file` references from command and skill files and runs them in the opencode container without any permission check (`bash: deny` doesn't apply), and that container's env holds the provider keys and the opencode password. Vault skills come from git, so anyone who can push to a vault repo could use it. The endpoint also can't carry the per-turn web switch. We rejected using it for its built-in argument handling; the backend does the `$1…$N` / `$ARGUMENTS` expansion itself (`apps/backend/src/harness/command.ts`). Any future use of the command endpoint, and each opencode upgrade, must re-check this (see [security.md](../../specs/system/security.md#confining-the-ai), #120).
